# Удалённый доступ через relay

Если LM Studio нужно открыть вне локальной сети, используйте relay из
`tools/lm-relay` в репозитории. Это отдельный небольшой сервер на VPS: агент на
машине с LM Studio открывает исходящее WSS-соединение, а приложение ходит на
`https://relay.example.com/d/<device>/…`.

Подробная установка: [tools/lm-relay/README.md](https://github.com/Spe4naz/lm-chat/blob/main/tools/lm-relay/README.md).

## В приложении

**Настройки → сервер → Изменить → Доступ через интернет (relay)**:

- адрес relay (HTTPS);
- ID устройства;
- токен relay (если пусто — используется токен плагина);
- при необходимости — сквозное шифрование E2E и публичный ключ агента.

Один origin заменяет LM Studio, мост и плагин. Порт `1237` (MCP) наружу не
выносится.

## E2E

Агент печатает ключ:

```bash
lm-relay-agent -config ~/.config/lm-computer/relay-agent.json -print-identity
```

Вставьте `public_key` в настройки relay и сверьте отпечаток. Relay видит только
непрозрачные кадры: пути, заголовки, токены и содержимое чатов ему недоступны.
При неверном ключе приложение сообщает об ошибке и не откатывается на открытый
режим.

## Статус

В **Настройки → Диагностика** есть карточка **Relay**: онлайн/офлайн, число
активных потоков, версия relay и режим `TLS`/`E2E`.

## Ограничения

- Нужен VPS и домен (или `sslip.io`); самоподписанный сертификат на IP требует
  пиннинга в приложении.
- Relay не входит в APK/EXE и обновляется отдельно.
- Наружу открываются только 80/443 VPS; домашняя сеть не слушает ничего нового.
